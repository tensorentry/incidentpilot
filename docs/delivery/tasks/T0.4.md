# T0.4 — CI workflow

**Milestone:** M0 Foundation · **Issue:** IP3-001 · **Status:** done

## 1. Understand

- Spec refs: §15.1 supply-chain row (pinned actions, trusted CI), §15.4 (deterministic no-key tests), §16.4 (`ci.yml`).
- Acceptance: green on GitHub with no secrets.
- Carried over from T0.2: `make check` had never run from a cold cache.

## 2. Plan

One workflow: install from the lockfile with no cache, then run `make check` with the network disabled.

## 3. Validate plan

- **Pinning:** actions pinned by commit SHA, with exact versions for the runner image and `uv`. Tags can be moved, so SHAs were looked up and confirmed to be commits, not tag objects.
- **Least privilege:** `contents: read`, `persist-credentials: false`, no secrets.
- **Cold cache:** `enable-cache: false`. The project is small, and each run proves a clean install.
- **Network:** `make check` runs in an empty network namespace, so the requirement is enforced on every PR.

**Out of scope:**
- The live evaluation workflow (`eval-live-opt-in.yml`) belongs to M6.
- Secret and image scanning (§15.1) belongs to the security work in M5.

## 5. Validate implementation

- `actionlint` passed with no findings. It was run once and isn't a project dependency.
- **The first green run wasn't enough.** The "Confirm the network is disabled" step would also pass if `curl` failed for an unrelated reason. So a throwaway PR added a test making a real request to PyPI, which passes locally.
- **The first red run was for the wrong reason.** Lint rejected an unused `noqa`, so the test never ran. It did show CI blocks on lint. The `noqa` was removed and the run repeated.
- The throwaway PR (#2) was closed and its branch deleted.
