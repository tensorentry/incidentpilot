# T4.5 — Provider call gate with minimal ledger

**Milestone:** M4 First live agent · **Spec:** §11.1, §11.2 (D14), §9.3 · **Errata:** E9, E18 · **Status:** done

## 1. Understand

- **Spec refs:**
  - **§11.1:** budget lives on the investigation and is reserved before dispatch. A request whose receipt is uncertain keeps a conservative reservation, "not a fabricated zero-cost settlement". No retry may bypass the ledger.
  - **D14** sets the order:
    1. lock the investigation and check state, epoch, deadline and quotas;
    2. reserve the request and its estimated maximum cost;
    3. dispatch;
    4. settle at actual usage, or mark `UNKNOWN` and keep the reservation.
  - **E18:** `DISPATCHED` commits before the request is sent. Sent calls keep their reservation.
  - **E9:** `close_attempt` turns a sent call `UNKNOWN`.
- **Already in place:**
  - The model-call ledger: reserve, dispatch, settle, fail, unknown and close, with counters checked against rows (T3.11).
  - The SDK settings: no retries, and checks that a wrapper can reserve before each request and settle after it (T4.1).
- **Open question:** the real model and its prices (spec §18.2-1) are settled at T1.6, which needs the API key.

## 2. Plan

- **`model_runtime/pricing.py`:**
  - `Pricing`, a versioned table in micro-USD per million tokens, with plain input, cached input, cache writes and output;
  - `input_token_bound`, `estimate` and `charge`.
- **`model_runtime/gate.py`:** `GatedModel`, an SDK `Model` that wraps another and runs D14 around every request.

**Acceptance:**
- Each request is reserved at a bound it can't exceed, and committed as `DISPATCHED` before the provider sees it.
- Each request is settled at the cost of the reported usage.
- A provider error, a lost connection, an answer without usage, a spent budget, a passed deadline, a lost lease and cancellation each leave the ledger as E18 and E9 say.

## 3. Validate plan

| Rule | How |
|---|---|
| Reserve before dispatch (D14) | The reservation and `DISPATCHED` each commit in their own fenced transaction before the wrapped model is called. A test reads the ledger from another connection while the provider answers |
| The estimate is an upper bound (§11.1) | Input is priced at the request's length as ASCII-escaped JSON, never less than its UTF-8 bytes, plus framing allowances, all at the dearer of plain input and cache writes. Output is priced at the whole cap, which the gate imposes on the request. Every division rounds up |
| No fabricated zero settlement (§11.1) | An answer whose usage shows no input tokens is unreported usage: the call becomes `UNKNOWN` and keeps its whole reservation as unknown cost |
| Uncertain receipt keeps its reservation (§11.1, E18) | A provider error status is `FAILED` with `PROVIDER_ERROR`. A connection error, a timeout or anything else is `UNKNOWN`. Both keep their cost, and the error is raised again |
| Denials send nothing (D14) | `reserve_call` raises `BudgetDenied` for a spent budget or a passed deadline, before any dispatch |
| Stale lease (§5) | The keeper is checked before each step, and each write is fenced. A lease lost while the provider answers fails the settlement, and the sweeper has already left the call `UNKNOWN` |
| No retry bypasses the ledger (§11.1) | The gate never retries, and T4.1 already pins the client and the SDK to one send per request |

**Decisions:**
- **Prices are an input, not a constant.** No price is written into the code. The real table arrives with the model choice at T1.6, under its own version. Tests use round numbers that match no provider.
- **Bytes bound tokens.** A byte-level BPE token holds at least one byte, so a request can't have more tokens than bytes. The provider's framing isn't in the bytes, so 16 tokens per item and 256 per request are added. These allowances are assumptions: T4.10 compares estimates with reported usage.
- **Cache writes have their own price.** The provider's usage reports tokens written to its cache, which can cost more than plain input. An estimate prices every input token at the dearer rate.
- **Cancellation writes nothing.** Writing to the database while a task is being cancelled would race the cancellation. `close_attempt` already turns the sent call `UNKNOWN`.

## 5. Validate implementation

**Found while testing:**
- **The provider's usage reports cache writes.** The first draft priced only plain and cached input. Cache writes now have their own price, a charge counts them, and an estimate covers them.
- **Schemas hold non-ASCII text.** The first draft counted UTF-8 bytes with `ensure_ascii=False`. Mutation testing showed `False` and `None` behave the same there. The gate now measures plain ASCII-escaped JSON, which is simpler. An escape is always longer than the UTF-8 bytes it stands for, so the bound still holds, and a test checks that for several scripts.

**Planted faults.** 15 were planted one at a time, and the first round caught all of them:

| Fault | Caught by |
|---|---|
| DISPATCHED committed after the provider answered | the ledger-seen-by-the-provider test, among 8 |
| Output cap not imposed | the output cap test |
| Missing usage settled at zero | the no-usage test |
| Provider error left `UNKNOWN` | the provider error test |
| Other failures not recorded | the unanswered request test |
| Cached input not discounted | the cache pricing test |
| Cache writes not charged | the cache pricing test |
| Keeper not consulted | the lost lease test |
| Settlement not fenced | the late answer test, among 5 |
| Request ID not recorded | the settlement test |
| Estimate ignores dearer cache writes | the estimate tests |
| Costs rounded down | the rounding test |
| Framing left out of the token bound | the bound test |
| Tool schemas not measured | the request size test |
| Output schema not measured | the request size test |

**Mutation testing.** The first run left 19 survivors, all in the gate, and was stopped early to fix them:
- **Arguments passed to the wrapped model unchecked.** Nothing showed that instructions, the output schema, handoffs, tracing, the previous response, the conversation or the prompt reached the provider (12 mutants). A test now calls the gate directly, gives every argument a distinct value, and checks that the provider gets them all unchanged except the output cap.
- **Instructions and the output schema left out of the estimate.** The test agents had neither (2 mutants). The same test checks that the reservation counts them.
- **Boundaries.** No test used an output cap of 1, or usage of exactly one input token (2 mutants).
- **JSON options that changed nothing:** `default=str`, never needed because the SDK passes plain dicts, and `ensure_ascii` (3 mutants). The request is now measured as plain ASCII JSON.

A targeted run then killed all 252 mutants in the gate and pricing modules, and the full run caught everything:

| Target | Result |
|---|---|
| `mutmut` | 5380/5380 killed |
| State edges | 124/124 caught |
| Enum values | 147/147 caught |
| Decorated functions | 164/164 caught |

The planted faults were re-run against the final code, and all 15 are still caught.
