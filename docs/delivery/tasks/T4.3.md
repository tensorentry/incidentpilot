# T4.3 — Gateway with evidence-before-exposure, one tool

**Milestone:** M4 First live agent · **Spec:** §7.2, §8.1, §8.4 (D11), §11.1 · **Errata:** E9, E13, E14, E18, E19 · **Status:** done

## 1. Understand

- **Spec refs:**
  - **§8.4 (D11)** sets the order of a call:
    1. schema, scope and size checks;
    2. reserve the global and per-tool quota behind the fence;
    3. ask the adapter;
    4. sanitize and persist the result, evidence, visibility and event behind the fence;
    5. only then return selectors.

    A stale or cancelled call gets no new evidence IDs.
  - **§8.1:** the model writes only tool arguments. Investigation, attempt, owner, epoch, snapshot and budgets come from trusted context.
  - **§11.1:** tool quotas are reserved before dispatch, and no retry may bypass the ledger.
  - **E13:** adds `tool_calls.tool_name` and an `investigation_tool_quota` row per tool. The global cap stays on the investigation.
  - **E18:** tool calls follow `RESERVED → DISPATCHED → COMPLETED|UNKNOWN|FAILED`, with `DISPATCHED` committed before the adapter runs. Sent calls keep their quota, unsent ones release it.
  - **E9:** `close_attempt` closes tool calls the same way it closes model calls.
  - **§7.2:** `tool_calls` is unique per `(attempt_id, invocation_id)`, and `tool_evidence` links a call to its evidence.
- **Already in place:**
  - The domain tool-call states, effects and close rules (T1.3).
  - The envelope (T1.8).
  - Evidence commit with dedup and visibility (T3.11).
  - The fixture adapter (T4.2).
  - `gateway_tool` and the SDK settings (T4.1).

## 2. Plan

- **Migration `0009_tool_calls`:**
  - `tool_calls`, `investigation_tool_quota` and `tool_evidence`, all owner-isolated;
  - global tool counters on `investigations`;
  - `TOOL_CALL_DISPATCHED` and `TOOL_CALL_UNKNOWN` events.
- **`persistence/tool_ledger.py`:**
  - reserve, dispatch, complete, fail and unknown, each moving both quotas by its E18 effect;
  - `close_tool_calls`, called from `close_attempt`.
- **Quota rows** are created with the investigation (E13).
- **`tools/gateway.py`:** `ToolGateway.call` runs D11 for any tool. `load_scope` reads the frozen services and window.
- **`tools/catalog.py`:** `get_service_metrics`, the one tool in this task, registered through `gateway_tool`.
- **`commit_evidence`** returns the sanitized content, so the model is shown exactly what was stored.
- **The published report** counts completed tool calls.

**Acceptance:**
- A metrics call through the SDK commits its evidence before the model sees an ID.
- Quotas match the rows at every step.
- A lost lease never shows the model an evidence ID.

## 3. Validate plan

| Rule | How |
|---|---|
| Scope checked before any reservation (D11) | The service must be in the frozen `allowed_services` and the window inside the frozen window. A refusal is `OUT_OF_SCOPE`, with no row and no quota |
| Arguments that make no query cost nothing | The tool builds the query first. A validation error is `INVALID_ARGUMENT`, with no row |
| Reserve both quotas atomically, behind the fence (D11, E13) | Two conditional `UPDATE`s inside one fenced transaction. A denial raised there rolls back whichever quota was already taken |
| DISPATCHED before the adapter (E18) | Its own fenced transaction commits first |
| Evidence before exposure (§8.4) | Evidence, visibility, `tool_evidence` and `COMPLETED` commit in one fenced transaction. The response is built only after it commits |
| Stale lease: no new evidence IDs (§8.4) | Any fenced step raises `StaleLease`. A lease lost while the adapter answers rolls the commit back, and the sweeper has already left the call `UNKNOWN` |
| Sent calls keep their quota, unsent ones release it (E18, E9) | The ledger applies `tool_call_effect`. `close_tool_calls` fails unsent calls with `STALE_LEASE`, `CANCELLED` or `INTERNAL_ERROR` by how the attempt ended |
| Counters match rows (§11.1) | CHECKs hold `dispatched <= reserved <= cap` on both levels. Tests compare counters to rows after every path |
| One invocation is one row per attempt (§7.2) | `UNIQUE (owner_id, attempt_id, invocation_id)`. The invocation ID is `uuid5(attempt_id, provider call ID)` |
| Context not model-writable (§8.1) | The tool's schema holds only its five arguments. Lease, owner and scope come from the gateway the run carries |
| Owner isolation (E19) | All three tables use `owner_isolation` with composite foreign keys. `tool_calls` also references its quota row, so a call can't name a tool that has no quota |

**Decisions:**
- **The invocation ID is derived, not taken from the model.** The envelope's `invocation_id` is a UUID. The provider's call ID is kept in `provider_call_id`, but nothing trusts it.
- **A source's refusal is `FAILED` and keeps its quota.** The adapter was asked, so the call was sent (E18).
- **Any other failure of the source raises.** The worker's attempt then closes, and E9 leaves the call `UNKNOWN`. A guess at `FAILED` could hide an adapter bug.
- **Investigations started before this migration have no quota rows,** so their tool calls are refused rather than unbounded.

## 5. Validate implementation

**Found while testing:**
- **`ToolContext` isn't exported from the SDK's package root in 0.24.0.** mypy accepted the import, but Python failed at runtime. It now comes from `agents.tool_context`.
- **The catalog check assumed every foreign key points at `(owner_id, id)`.** `tool_calls → investigation_tool_quota` points at `(owner_id, investigation_id, tool_name)`. The check now requires a key that leads with the owner and targets the parent's whole primary key, which is the property that matters.
- **The isolation suite's extra tool-call investigations held both capacity slots,** so later claims failed. The fixture now cancels them, which also exercises closing their calls.
- **The migration tests pin the head revision.** It moved to `0009`.

**Planted faults.** 18 were planted one at a time:

| Fault | Caught by |
|---|---|
| Scope check skipped | the out-of-scope test |
| Window not checked against the scope | the out-of-scope test |
| Response built before the evidence commit | the evidence-before-answer test |
| DISPATCHED committed after the adapter ran | the refused-query test |
| Lease keeper not consulted | the keeper test |
| A source's refusal not recorded | the refused-query test |
| Partial coverage reported as `ok` | the partial-answer test |
| Per-tool quota not checked | the per-tool quota test |
| Global quota not checked | the global quota test |
| Release not applied to unsent calls | the lost-attempt test |
| Evidence not linked to its call | the evidence-before-answer test |
| Tool calls not closed with the attempt | the lost-while-answering test |
| Cancellation closes calls as `STALE_LEASE` | the cancellation test |
| Quota rows not created at start | the starting-quota test |
| Unsanitized content shown to the model | the sanitized-content test |
| Invocation ID not tied to the attempt | the recovery-invocation test |
| Quota CHECK dropped from the schema | the schema test |
| `tool_calls` not owner-isolated | the cross-owner suite |

The first round missed two of them:
- **Unsanitized content:** no fixture holds a secret, so raw and sanitized content were identical. A test source now returns a canary secret, and the model must see it redacted.
- **Invocation ID:** nothing showed that the ID depends on the attempt. A recovery attempt that reuses the model's call ID must now get a new invocation.

**Mutation testing** left 31 survivors and 18 timeouts on the first run:
- **`mark_tool_call_unknown` was never called** (8 mutants with no tests). E9's close path is the only way a tool call becomes `UNKNOWN`, so it was removed.
- **Mutants that changed nothing:**
  - `zip(strict=True)` on lists that always match;
  - an `"arguments"` fallback for an error location that can't be empty;
  - `include_input`, whose output was never read;
  - a `QuotaDenied.per_tool` attribute nobody read;
  - `error and error.value` where the error is always set.

  The commit loop now builds selectors and records as it goes. `QuotaDenied` takes the tool, or `None` for the global quota, so its message is the only output. The payload takes the error code directly.
- **Behaviour no test pinned:**
  - the stored `arguments_sha256` and `provider_call_id`;
  - an `EMPTY` answer;
  - cutting a long refusal to the envelope's 500 characters;
  - `INTERNAL_ERROR` for unsent calls when an attempt ends `FAILED`;
  - the ledger's two error messages;
  - event payloads naming the real call ID. The old test compared the first event's ID with the later ones, so `str(None)` everywhere passed.

  Each now has a test.
- **The 18 timeouts** were in modules this task barely touches. The run took five hours against about fifty minutes normally, because the machine slept.

The second run left 2 survivors and 33 timeouts:
- **`load_scope` raised a `LookupError` for a missing investigation.** That can't happen, because a lease's investigation always exists, so no test could pin the message. It's now an assertion.
- **A paged answer's cursor** reached the model untested. A test source now returns a second page, and the response must carry its cursor.
- **The timeouts weren't the machine sleeping.** mutmut sets each mutant's time limit from the measured duration of the tests that cover it, and that measurement leaves out fixture setup. The isolation suite runs a whole investigation in its fixtures, so code it covers got a budget of seconds for a test that needs much longer. `[tool.mutmut]` now sets `timeout_constant = 10`, which adds a fixed allowance to every limit.

The last run left 16 timeouts. Each was re-run alone and killed. Three of them were in this task's code: the `EMPTY` status, and two that drop the completed call's result status, which the `result_by_state` CHECK refuses.

**Limits:**
- Only `get_service_metrics` is registered. The other four tools are T4.4.
- There are no byte limits on a response yet. Pages and series are bounded by T4.2, and the briefing budget is T4.6.
- A replayed invocation in the same attempt fails on the unique key instead of returning its stored answer. The SDK promises not to replay a completed call within a run.
- Physical retries aren't counted, because the fixture adapter never retries.
