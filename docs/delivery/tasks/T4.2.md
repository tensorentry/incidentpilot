# T4.2 — Fixture telemetry adapter

**Milestone:** M4 First live agent · **Spec:** §8.1, §8.3, §8.5, §9.1 · **Errata:** E15, E16 · **Status:** done

## 1. Understand

- **Spec refs:**
  - §9.1 defines `TelemetryProvider`, and E16 adds `trace_summary`, so there are five methods.
  - §8.1 says which arguments the model may write for each tool.
  - §8.3 sets the telemetry rules:
    - windows are UTC and half-open;
    - coverage tells no-data apart from zero;
    - log paging is stable, with a snapshot-bound cursor and deterministic sort keys;
    - naming a service can't widen scope;
    - sizes are enforced before anything reaches the provider;
    - there is no query language.
  - §8.5 requires each evidence row to carry `adapter_version`.
  - E15 says one evidence row is the smallest citable record, and a series counts as one record.
- **Already in place:**
  - T2.1–T2.3 built the observation bundle and three snapshots.
  - T3.2 imports each bundle with a digest of its content.
  - T1.4 provides `EvidenceDraft`, and T1.8 provides `Coverage`.
- **Not in this task:**
  - The gateway, T4.3, checks the investigation's frozen scope and window, holds quotas and the fence, commits evidence, and builds the tool envelope.
  - The tools themselves and the arguments they expose to the model are T4.3 and T4.4.

## 2. Plan

- **`domain/telemetry.py`** defines:
  - five query contracts, holding only model-writable fields;
  - `SourceResult`, which carries evidence drafts, coverage and paging;
  - `QueryRejected`, which carries a tool error code;
  - the `TelemetryProvider` protocol.
- **`adapters/fixture.py`** provides:
  - `FixtureTelemetry`, which answers from one bundle;
  - `open_fixture`, which reads a snapshot's bundle and refuses it unless it matches the digest stored at import.

**Acceptance:**
- Every query returns E15 rows and coverage that never reports missing data as present.
- Off-graph services and edges are refused.
- Paging is deterministic, and a cursor only continues its own query in its own snapshot.

## 3. Validate plan

| Rule | How |
|---|---|
| One row per citable record (E15) | **Metrics:** one row per series and window, with its points, and source ref `metric/<service>/<metric>/<res>s/<start>/<end>`. **Dependencies:** `dependency/<caller>/<callee>/…`. **Logs, deployments and span summaries:** one row each, with `log/…`, `deployment/…` and `span/…` |
| Half-open UTC windows (§8.3) | `start <= t < end` everywhere, and the windows are T1.1's UTC `TimeWindow` |
| Missing data is never zero (§8.3) | **Metrics:** each missing grid point is a gap, including points outside the snapshot. **Logs and deployments:** the part of the window outside the snapshot is a gap. **Traces:** only time covered by a summary counts. A metric series with no points produces no row |
| Stable paging with a snapshot-bound cursor (§8.3) | Sorted by (time, record ID). The cursor is `<scope>_<position>`, where the scope is a digest of the snapshot ID and the query without its cursor. A snapshot never changes, so a position in its sorted matches is stable. Any other cursor is `CURSOR_INVALID` |
| Scope can't be widened by naming a service (§8.3) | A service outside the graph and a dependency that isn't an edge are both `OUT_OF_SCOPE`. Dependency series never mix with the service's own |
| Sizes bounded before exposure (§8.3) | Pages hold at most 100 records. A metric window holds at most 10,000 points. At most 50 gaps |
| No query language (§8.3) | The log filter is a literal match that ignores case, at most 100 characters |
| `adapter_version` on each row (§8.5) | Taken from the snapshot's manifest |
| Oracle never reachable (E12) | The adapter reads only the observation bundle. The import-boundary test from T2.1 still passes |

**Decisions:**
- **A metric window must sit on the series' grid.** A window that cuts a point in two has no honest coverage, so it is refused with the grid's start and step. Whole minutes always fit the fixtures.
- **Only the recorded resolution is offered.** Downsampling a histogram is possible, but no fixture needs it yet. The refusal names the resolutions that exist.
- **An unknown metric is refused and the refusal lists what exists.** Answering empty would let the model read "no errors" from a metric that was never recorded.
- **When there are more than 50 gaps, the last gap widens to cover the rest.** That may report data as missing when it is present, but never the reverse.
- **`samples` is the number of records in the page,** or points for metrics.

## 5. Validate implementation

**Review findings fixed before testing:**
- The first draft computed trace coverage twice. `_page` now takes the covered windows from its caller.
- A cursor holding a timestamp with no timezone would have failed later, on comparison, instead of being refused. That cursor design was later replaced (see mutation testing below).
- Nothing bounded a metric window. A year at one-second resolution would have built millions of gap slots, so it is now capped at 10,000 points.

**Planted faults.** Mutation testing can't express these, so 16 were planted one at a time:

| Fault | Caught by |
|---|---|
| Folding gaps drops the later ones | the gap-limit test |
| The cursor isn't bound to the snapshot | the other-snapshot test, and the cursor format test |
| The cursor isn't bound to the query | the other-query test, and the cursor format test |
| Trace coverage taken from the snapshot instead of the summaries | three trace tests |
| The whole series returned, whatever the window | the sub-window and outside-window tests |
| Missing slots not counted | four coverage tests |
| The digest not checked on open | the changed-bundle test |
| The snapshot ID not checked on open | the renamed-bundle test |
| Off-grid windows accepted | the grid test |
| Dependency edges not checked | the edge test |
| Logs from every service | six log tests |
| Severity ignored | the severity test |
| A case-sensitive filter | the filter test |
| Dependency series mixed with the service's own | two metric tests |
| The cursor position not checked | the position test |
| No cap on points | the point-cap test |

**Mutation testing** left 19 survivors in the adapter on the first run:
- **Eleven were in the first cursor design:** JSON, then base64, holding the last sort key. Changing its key names, separators, digest length or padding arithmetic broke nothing a test could see, because any consistent encoding works. The cursor is now `<scope>_<position>`. That removes the encoding and the timezone check, and a golden test pins its format so a change to it is deliberate.
- **Four came from dumping the query in JSON mode, which was redundant.** The canonical digest already normalises times, so it was removed.
- **A window that only touches the snapshot's edge, or lies wholly outside it,** wasn't tested for logs or traces. A mutant that turned an empty overlap into a zero-length window would have crashed there. Both now have tests.
- **The refusal that lists several resolutions** wasn't tested with more than one.
- **`len(gaps) <= MAX_GAPS` against `<`** made no difference at exactly 50 gaps, because the folded tail equals the last gap. Folding is now written as kept and rest, which has no such boundary.

After the fixes, a last survivor remained: `partition` against `rpartition` on the cursor. They differ only when the scope contains `_`, and a hex digest never does. The cursor is now read with `removeprefix`, which has no such twin.

**Timeouts:** the runs also reported timeouts in persistence and recovery code this task doesn't touch:
- 17 on the first run;
- 4 on the second;
- 28 on the last.

Each run overlapped the machine sleeping or other work on the same database. Every one was re-run alone on an idle machine and killed.

**Limits:**
- The adapter doesn't know the investigation's window. Clamping a query to the frozen incident scope is the gateway's job (T4.3).
- `clock_caveat` is always null, because the fixtures have no clock skew.
- Downsampling isn't supported (see §3).
