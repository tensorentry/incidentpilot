# T3.13 — Kill/restart demo

**Milestone:** M3 Durable slice · **Issue:** IP3-004 · **Status:** done

## 1. Understand

- Spec refs:
  - §16.2 Phase 1 exit: kill/restart resumes safely; one final report; the old epoch can't commit.
  - §6.3 crash matrix: "after provider receives request, before response is persisted": the call becomes `UNKNOWN` and keeps its reservation. "Worker loses lease while external call in flight": the stale commit is rejected, tested with "two workers + delayed fake provider".
  - §6.1: every worker also sweeps, so a worker that comes up recovers lapsed leases.
  - IP3-004 exit: two workers contend, a stale report commit fails, and there's one final report.
- Errata:
  - **E9:** a lost attempt's dispatched calls become `UNKNOWN`.
  - **E10:** the CLI calls application services directly until the API exists.
- Already in place:
  - The worker loop and lease keeper (T3.9).
  - The sweeper (T3.10).
  - The scripted model (T3.11).
  - Publication (T3.12).

  What's missing is a process to run them in, and a demo that kills that process.

## 2. Plan

- **`incidentpilot worker`:** runs the worker loop with the scripted model and the sweeper as maintenance. It refuses any mode but `offline_demo`.
  - `--jobs N` stops it after N investigations have ended.
  - `--lease-seconds` sets the lease length, with renewal at a third of it.
  - `--provider-delay` slows the fake provider, so a call can be caught in flight.
- **`workflows/offline.py`:** assembles that worker. It also has a `Shift`, which counts ended jobs and sets the stop event.
- **`ScriptedModel.provider_delay` and `DEMO_SCRIPT`:** a three-step script with fixed log records.
- **`scripts/kill_restart_demo.py`** (`make demo`), which drives real processes through two scenes:
  1. **Kill and restart:** SIGKILL worker A while its first call is `DISPATCHED`, then start worker B.
  2. **Stale worker:** SIGSTOP A mid-call, let B recover and publish, then SIGCONT A and see its commit refused.

  After each scene it checks the database and exits non-zero on any mismatch.

**Acceptance:** the demo passes against a scratch database in the integration suite. Each scene ends `COMPLETED` at epoch 2 with one report, attempt 1 `LOST` and attempt 2 `SUCCEEDED`, and A's in-flight call `UNKNOWN`. In scene 2, A logs the `StaleLease` refusal.

## 3. Validate plan

| Rule | How it holds |
|---|---|
| Kill/restart resumes safely (Phase 1 exit) | Scene 1 kills a real process with SIGKILL. The restarted worker's sweep marks the attempt `LOST` and schedules the retry, and its claim takes epoch 2 |
| One final report (invariant 1) | Each scene checks `count(diagnosis_reports) = 1` |
| The old epoch can't commit (§6.1) | Scene 2 resumes a real stale process, whose next commit, settling its call, goes through the fence and is refused |
| An in-flight call stays conservative (§6.3, E9) | A's `DISPATCHED` call is `UNKNOWN` after recovery, never `SETTLED` |
| Workers sweep (§6.1) | The worker command's maintenance is `sweep`. A test has it recover a dead worker's investigation |
| The demo makes no network calls and needs no keys | `offline_demo` only. The worker command refuses other modes |

**Deviations and decisions:**
- **The demo's evidence is written into the script,** not read from the snapshot. The telemetry adapter that reads snapshots is T4.2. The README says the model is scripted.
- **The freeze waits for a quiet moment.** A worker frozen inside a transaction would hold the investigation's row lock, and the recovering worker would wait on it forever. So the demo checks `pg_stat_activity` after each SIGSTOP, and if the worker is mid-statement it resumes it briefly and tries again.
- **No signal handling in the worker:** SIGTERM and SIGKILL both leave the lease to lapse, and the sweeper recovers it. A graceful drain can come with the API (IP3-010) if it's wanted.
- **The worker counts a failed job toward `--jobs`.** The stale worker in scene 2 exits once its refused job ends.

## 5. Validate implementation

**First runs of the demo:**
- **The investigation and incident IDs are named `id` in the CLI's JSON,** not `incident_id` or `investigation_id`.
- **Failure categories are stored in upper case,** so the expected `LEASE_LOST` was corrected.
- **A 60-second provider delay made scene 2 take a minute.** SIGSTOP doesn't pause the clock, so the frozen worker woke with most of its wait still to run. With 10 seconds, the call is still caught in flight, and the whole demo takes about 16 seconds.

**Planted faults.** Three faults were planted one at a time to check that the demo fails when recovery breaks. All three were caught:

| Fault | What the demo reported |
|---|---|
| The worker doesn't sweep between claims | worker demo-b didn't finish in 60 seconds |
| A lost attempt's calls are left open | the investigation didn't end as recovery promises |
| The fake provider ignores its delay | worker A never dispatched a call |

**Mutation testing** found 21 survivors on the first run:
- **Seventeen were in the demo script's records.** They were built by a function that only ran at import, so no test was recorded as covering it. The records are now module-level data, which mutmut leaves alone like the other module constants.
- **Four timed out instead of failing.** The mutants accepted `--jobs 0` or lost the shift, so a worker never stopped and its test hung:
  - The integration tests now run the worker command in the test's own event loop, under a 20-second deadline.
  - The unit tests for bad options clear the database setting, so a value wrongly accepted fails on configuration instead of starting a worker.

The mutation run itself needed `scripts/` copied alongside the tests, since the demo test runs the script.

After the fixes:

| Target | Result |
|---|---|
| `mutmut` | 4045/4045 killed |
| State edges | 124/124 caught |
| Enum values | 145/145 caught |
| Decorated functions | 164/164 caught |

**Also fixed:** when it fails, the demo now kills every worker it started, so a frozen one isn't left behind holding connections.

**Limits:**
- **The scripted model isn't an investigator.** Its candidate is the abstention from T3.12.
- **The demo needs a POSIX system** for SIGSTOP and SIGCONT, which macOS and the Linux CI runner both are.
