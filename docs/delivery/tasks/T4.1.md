# T4.1 — Remaining SDK compatibility checks

**Milestone:** M4 First live agent · **Spec:** §9.1, §9.3, §9.4 · **ADRs:** ADR-004, ADR-007 · **Status:** done

## 1. Understand

- **Spec refs:**
  - §9.3 requires a small isolated test against an exact pinned SDK release. It must verify eight behaviours rather than assume them.
  - §9.1 says the SDK owns turn sequencing and tool execution, and an `InvestigatorRunner` shields the rest of the system from SDK types and failures.
  - §9.4 lists the endings that need an explicit outcome: refusal, provider timeout, turn exhaustion and budget cutoff.
  - §16.4 puts the adapter in `model_runtime/` and the tests in `tests/sdk_compat/`.
- **Split with T1.6:**
  - T1.6 is the paid spike and stays blocked on the API key and spend cap. It covers what only a real model can show: whether the provider accepts the candidate schema in strict mode, and how often a model follows it.
  - This task covers everything the pinned SDK decides on its own. That runs offline, with a fake model, in `make check`.
- **Starting point:**
  - No SDK installed yet.
  - `Settings.trace_export_enabled` is only a flag. T0.3's record left proving the SDK's own tracing is off to this task.
  - `CandidateOrStop` and `StopReason` exist (T1.5).
  - `BudgetDenied` comes from the ledger (T3.11).

## 2. Plan

- **Pin `openai-agents==0.24.0`,** the latest release, a month old. `openai` and `httpx2` become direct dependencies too, because the adapter imports them.
- **`src/incidentpilot/model_runtime/sdk.py`** holds every SDK setting the worker relies on:
  - `run_config()` and `model_settings()`;
  - `candidate_output()`, for strict structured output;
  - `gateway_tool()`;
  - `provider_client()`;
  - `stop_reason()`, which maps each SDK ending to a `StopReason`.
- **`tests/sdk_compat/`** runs the real SDK against `FakeModel`, which plays back one response per turn. Each setting that departs from a default has a control test that shows the default, so a pass proves the setting does the work.
- **`make test`** also runs `tests/sdk_compat`, so CI runs it with no network.

**Acceptance:** each §9.3 item has a passing test or is named as T1.6's, and each setting fails a test when it is planted back to the SDK default.

|---|---|---|---|
| 1. Typed output maps to the candidate | `AgentOutputSchema` makes a strict schema and rewrites `oneOf` as `anyOf`. A valid answer arrives as a `ReportCandidate` | `candidate_output()`. | 5. | 6. Cancellation is best effort and can't bypass a fence | Cancellation reaches the running tool as `CancelledError`. **By default a tool's exception becomes text for the model** | `gateway_tool()`: `failure_error_function=None`, and the exception is carried in `ToolFailed` | A `StaleLease` ends the run and `stop_reason()` raises it again as itself. The control shows the default feeding it to the model. The fence itself is T3.6's |
| 7. SDK tracing disabled explicitly | **Tracing is on by default** | `set_tracing_disabled(True)` at import, plus `tracing_disabled=True` per run | A spy processor sees nothing, with and without the run setting. The control switches tracing on and the spy sees the run |
| 8. Callbacks, retries and tracing match the pinned release | See findings below | All of the above | `test_the_installed_sdk_is_the_pinned_release`, plus the config tests |

**Decisions:**
- **Invalid output is a provider failure.** `StopReason` has no separate value for it, and the provider is the side that broke the strict schema. The detail written with the stop says which.
- **`BudgetDenied` isn't mapped here.** It reaches the caller unwrapped, and the gate (T4.5) and fallback (T4.8) choose between `budget_exhausted` and `deadline_reached`.
- **A deadline is `asyncio.timeout` around the run,** not an SDK setting. The runner (T4.7) turns it into `deadline_reached`.
- **The provider may still send several calls in one response.** Running them one at a time keeps quotas exact and lets them share the worker's one connection. Whether to ask the provider for one call per response is T4.7's choice.

## 5. Validate implementation

**Findings about the pinned release** (§9.3 item 8: it differs from web documentation):
- **`openai` 3.x uses `httpx2`, not `httpx`.** Client types, `MockTransport` and exception requests all come from `httpx2`.
- **The provider client retries twice by default.** One reserved call could become three provider requests. `provider_client()` sets `max_retries=0`, and a test shows the default sends three.
- **`tool_not_found_behavior`** takes `raise_error` or `return_error_to_model`.
- **The strict schema keeps `discriminator` and `format`.** Whether the provider accepts them is for T1.6.
- **The SDK adds 34 packages,** including `mcp`, `starlette`, `uvicorn` and `websockets`, which the worker doesn't use.

**Tracing in tests:** the spy replaces the SDK's exporter rather than joining it, so the control test that switches tracing on can't send a trace anywhere, even when a developer has `OPENAI_API_KEY` set. An earlier draft added the spy beside the exporter. With no key set, it printed "skipping trace export" at exit.

**Planted faults.** Each setting was put back to the SDK's default, or a mapping changed, one at a time:

| Fault | Caught by |
|---|---|
| Tool calls run at once | the quota test and the config test |
| Tool exceptions go to the model | the failing-tool test |
| The gateway lets a tool's exception through unwrapped | the failing-tool test |
| SDK retries a request | the config test |
| Provider client retries | the client test |
| Tracing on for the run | the config test (tracing stays off process-wide) |
| Tracing on process-wide | the test that runs without the run setting |
| Sensitive data in traces | the config test |
| An unknown tool is reported to the model | the unknown-tool test and the config test |
| A loose output schema | both schema tests |
| A loose tool schema | the tool schema test |
| A refusal reported as a provider failure | the refusal test and the mapping test |
| A tool failure reported as a stop | the failing-tool test |
| An unknown error reported as a provider failure | the unchanged-error test |
| A wrong pinned version | the pin test |

All 15 were caught. The first plant of the unknown-tool fault used a value the SDK doesn't accept (`return_error`), and the SDK quietly kept its default. With the real value, `return_error_to_model`, both tests fail.

**Mutation testing** left 8 survivors on the first run:
- **Four were the SDK's own defaults written out:** a strict output schema, strict tool schemas, and stopping on an unknown tool. Removing them changed nothing. They are now left to the defaults, which the tests pin, so an upgrade that changes one still fails.
- **`ToolFailed`'s message wasn't checked.** The failing-tool test now checks it.
- **Losing `base_url` went unnoticed,** because the mock transport answered any host. The client test now checks the URL.
- **Losing `http_client` crashed the test process instead of failing it.** The client fell back to its own connection, and looking up the system proxy in a forked process on macOS crashed. `tests/sdk_compat/conftest.py` now sets `no_proxy` and refuses DNS and connections, so such a mutation fails with a connection error, and no SDK test can reach the network on a developer's machine either.

After the fixes:

| Target | Result |
|---|---|
| `mutmut` | 4079/4079 killed |
| State edges | 124/124 caught |
| Enum values | 145/145 caught |
| Decorated functions | 164/164 caught |

**Mutation run time:** in T3.14 the full-suite phases took hours, because each run started with the integration tests. `scripts/mutate.py` now runs the unit and SDK tests first, so a mutation they catch never waits on PostgreSQL. It also aborts if a test directory is missing from that list.

## 6. Test

- `make check` passes offline with 1467 tests, and 1 skipped because the network test only runs in CI. Of these, 36 are new, in `tests/sdk_compat`:
  - 8 on the output schema, valid and invalid answers, and refusals;
  - 8 on tool calls, the context and failing or cancelled tools;
  - 20 on reservations, turn limits, deadlines, stop reasons, tracing, retries and the pin.
- `make test-integration` passes with 378 tests, unchanged.

**Limits:**
- Everything here runs against a fake model. Whether a real model produces a valid candidate, and whether the provider accepts the schema, is T1.6, which is blocked on the API key and spend cap.
- `ModelTimeoutError` is mapped from a constructed exception. The SDK raises it only when a per-request timeout is configured, and none is yet.
