# T3.3 — Minimal sanitizer

**Milestone:** M3 Durable slice · **Issue:** IP3-004 · **Status:** done

## 1. Understand

- Spec refs:
  - D04: untrusted content passes through *normalize, redact, bound* before it reaches the gateway or storage. "Redaction is performed before persistence and before provider transmission."
  - §14.5: a fake secret canary in telemetry is removed before model requests, event storage and trace export.
  - §15.1: secret exposure is mitigated by "synthetic data, sanitizer before model and persistence", verified by canary checks.
  - §15.2: run metadata records the sanitizer version.
- Erratum E14: evidence dedup includes `redaction_version`, and `domain/evidence.py` already carries it.
- **Why now:** T3.4 stores the first untrusted text, an incident description. The plan puts the sanitizer before anything persists, so stored text never needs re-cleaning.

## 2. Plan

`policies/redaction.py`, where §16.4 puts redaction: one pure function, `sanitize(text, *, limit) -> Sanitized`. It does three things, in order:

1. **Drop characters**, after mapping CR, CRLF and the Unicode line separators to `\n`:
   - controls other than tab and newline, including NUL, which PostgreSQL can't store;
   - format characters: bidirectional overrides and isolates, zero-width characters, the byte order mark and Unicode tag characters;
   - unpaired surrogates, which can't be encoded as UTF-8.

   Then normalize to NFC.
2. **Redact** with a fixed rule table: private-key blocks, credentials in URLs, JWTs, AWS access keys, GitHub tokens, `sk-` provider keys, Slack tokens, bearer tokens, `password=`-style assignments, the canary `ip-canary-<16 hex>`, and email addresses. Each becomes `[REDACTED-<kind>]`.
3. **Bound** to `limit` characters, ending with `…[truncated]` when cut.

`Sanitized` reports counts per kind, dropped characters and whether the text was cut. It never reports the values. `SANITIZER_VERSION = "1"`.

**Acceptance:**
- each shape is redacted and its near misses pass unchanged;
- hidden characters can't split a secret;
- output is bounded, storable and stable under a second pass;
- pathological input stays fast.

## 3. Validate plan

| Requirement | How it holds |
|---|---|
| Before persistence and provider (D04) | A pure function with no I/O, so every write path can call it. T3.4 is the first |
| Canary removed (§14.5) | A rule with no word boundaries, so a canary glued to other text still goes |
| Version recorded (§15.2, E14) | `SANITIZER_VERSION`. A test pins a digest of the rule tables to the version, so changing a rule without a new version fails |
| Bounded | Output never exceeds `limit`. Text past `limit + 512` isn't examined, which bounds the work |
| Untrusted text can't hide instructions from a reviewer (§15.1) | Bidirectional, zero-width and tag characters are dropped before anything is shown or stored |

**Decisions of mine:**
- **Read past the limit before cutting.** A secret that straddles the limit is redacted whole rather than cut into a prefix the rules no longer recognise.
- **Markers contain no colon or `@`,** so a marker never looks like the credentials it replaced.
- **Over-redact generic keys.** `token: expired` becomes `token: [REDACTED-credential]`. Missing a credential costs more than losing a word, and a test documents this.
- **Not covered:** names, phone numbers, IP addresses and free-form personal data. Fixtures are synthetic (§15.1), so this is a safety net. A real-telemetry adapter (P2) would need a stronger one.

## 5. Validate implementation

**A fuzz test found a real leak.** Two hundred seeded random strings, built from secrets, fragments and hidden characters, must each come out the same on a second pass. Nine didn't. One cause leaked a credential:
- Rules ran once, in order, and a rule can only match once an earlier redaction has created its word boundary. In `…ip-canary-0123456789abcdefpassword=ABCD…`, no boundary precedes `password` until the canary is replaced. The canary rule runs after the credential rule, so the first output kept `password=ABCD…` in the clear.
- **Fix:** redaction repeats until no rule matches. Markers never match a rule, so each pass consumes only original text, and the loop always ends. Tests cover the canary-then-password and canary-then-bearer cases.

Two other causes made output unstable without leaking:
- **Truncation cut a marker in half,** and half a marker isn't recognised, so a second pass redacted it again. The cut now falls before a marker rather than through it.
- **A separator could reach across a newline,** so `password=` at the end of one line redacted the next line's first word. Separators now allow only spaces and tabs.

**Other fixes:**
- URL redaction swallowed the `@`. It now leaves it in place.
- The fuzz test first claimed a bare string of letters couldn't survive, which isn't a secret shape. The claim was wrong and is gone.
- The canary rule's word boundaries let `aip-canary-…` through; they're removed.

**Mutation testing** found ten gaps on the first run:
- **Seven in `_cut`, including a real bug.** If the cut fell inside a marker's own `[REDACTED-` prefix, as in `[REDA`, the search couldn't see the marker, so it was split. The search now finds any marker that starts before the cut. New cases cover two markers, a marker at position 0, a stray `]` after a marker, a `]` exactly at the cut, and one character either side of a marker. One survivor, passing `None` instead of `0` as the start, was equivalent; rewriting the line removed it.
- **Three in the redaction loop.** Mutants that flipped its exit condition spun forever, which the harness counts as not caught, and one corrupted the match counter the exit relied on. The loop is now recursion that repeats while the text changes. A flipped condition fails at once, either with a recursion error or by returning unredacted text, and a counter no longer decides when to stop.

## 6. Test

- `make check` passes offline with 1300 unit tests, and 1 skipped because the network test only runs in CI. That includes 200 seeded fuzz cases, each checked for stability, bounds, storability and the canary.
- `make test-integration` passes with 55 tests. Nothing in the database changed in this task.

**Limits:**
- **The version pin covers the rule tables, not the functions.** A change to how the functions behave needs the same version bump, by discipline, and the pin's comment says so.
