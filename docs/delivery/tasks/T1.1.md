# T1.1 — Domain vocabulary

**Milestone:** M1 Contracts · **Issue:** IP3-002 · **Status:** done

## 1. Understand

- Spec refs: §3.2 identities, §5.2 and D06 investigation states, §6.1 attempt statuses, §6.6 retry rules, §7.2 model-call states, §7.3 and §12.1 digests, §3.3 invariant 6.

- Digests are stored and compared later, so their output can never change.

## 3. Validate plan

- **Scope:** lifecycle vocabulary and invariant 6's three separate fields only. Evidence, tool and report-field enums arrive with their contracts in T1.3, T1.4, T1.5 and T1.8. `ActionProposalId` waits for IP3-014.
- **Dependency direction:** `RunMode` moved from `settings` into `domain`, so the domain doesn't depend on process configuration.
- **Reject rather than coerce:** anything without one unambiguous encoding raises, because a silently different digest is worse than an error.
- **Errors never contain values,** which may be sensitive.
- **Authored beyond the spec:** the spec names only two event types and a few termination reasons. The other `EventType`, `TerminationReason` and `FailureCategory` members are mine, and later tasks may extend them.

## 5. Validate implementation

**A false result, caught and redone.** The first mutation run reported 28 of 28 caught, but `make check` was already red, so every "caught" was just that existing failure. Those results were discarded. The mutation script now aborts on a red baseline and names the test that caught each mutation.

**The red test was a test bug.** A `StrEnum` member hashes equal to its string, so `{Colour.RED: 1, "red": 2}` is one key before the code sees it. A real collision needs a plain `Enum` with a string value, and the test now uses one.

## 6. Test

`make check` passes with 80 tests.

**Limits:**
- **Numbers:** `1` and `1.0` encode differently, so callers need consistent types. T1.5's `Measurement` must fix one numeric type.
- **Unicode:** strings aren't normalized, so visually identical NFC and NFD text gets different digests. That's deliberate, since evidence content is preserved exactly.
- **Types:** `Decimal` and `date` are rejected for now. Support can be added if a contract needs them, but adding a type must not change existing output.
- **IDs:** the separation is compile-time only. At runtime, `NewType` IDs are plain UUIDs.
