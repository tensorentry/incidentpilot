# T2.2 — Seeded generator and first case

**Milestone:** M2 Fixtures · **Issue:** IP3-003 · **Status:** done

## 1. Understand

- Spec refs: §14.1 (case `case-7Q2`: checkout latency after an inventory-affecting deploy, with span timings that point at the mechanism), D17, §14.4 (fixture seed and generator version in the manifest), and §8.3 (span or dependency timing needed to verify a synchronous wait).
- Errata: E12 (the generator lives in `evaluation/`), E15 (units of evidence), E16 (trace data).
- The case has to be diagnosable from telemetry, without being given away by names. The deploy's timing alone isn't proof (§9.2 prompt: "A nearby deployment is not proof"), so a decoy deploy shares the window.

## 2. Plan

- **`evaluation/telemetry.py`:** builders for counters and latency histograms, all drawing from the caller's seeded `Random`.
- **`evaluation/cases.py`:** `synchronous_dependency(seed)`, plus the list of committed cases.
- **`evaluation/generate.py`:**
  - writes each case as canonical JSON to `scenarios/observations/` and `scenarios/oracle/`;
  - `make fixtures` runs it.
- **`CauseCategory`:** a fixed list replacing the open category pattern from T1.5 and T2.1.

**Acceptance:** the same seed gives identical bytes.

## 3. Validate plan

- **Reproducible by construction.**
  - Every draw comes from one `Random(seed)`, and only `random`, `gauss` and `lognormvariate` are used.
  - Output goes through `canonical_json`, which fixes key order, float form and time format.
  - A test regenerates the case and compares bytes.
  - A second test compares the committed files with a fresh run, so the files can't drift from the code.
- **The case carries the signals §14.1 asks for.** Tests check each one in the data:
  - checkout's p95 latency at least doubles during the incident;
  - checkout calls inventory at least three times as often, while each call stays as fast as before, and so does inventory itself;
  - span summaries show checkout's time waiting on inventory rising at least fivefold, while its own time and its wait on payments stay flat;
  - an unrelated payments deploy happens earlier, as a decoy;
  - warnings appear only during the incident.
- **Nothing gives the answer away by name.**
  - The snapshot ID is a hash of family and seed.
  - The incident summary only says "Checkout requests are slow".
  - The deploy note says what changed ("Check stock for each cart item…"), as a real change record would. It never mentions latency or synchronous calls.
- **The oracle is on the evaluator side (E12).** It's written only to `scenarios/oracle/`, and the T2.1 boundary check still passes.

**Decision: a fixed category list.** I flagged the category vocabulary as open in T2.1. Grading compares categories exactly (§14.3), and strict structured output works best with enums, so `CauseCategory` replaces the pattern. It has five values, wider than the cases need, so that picking a category is a real choice for the model:
- `deployment_regression`
- `dependency_degradation`
- `resource_saturation`
- `traffic_surge`
- `configuration_change`

**My own choices:** the shape of the case (services, timings and magnitudes), the histogram bucket bounds, and the seed (7).

## 5. Validate implementation

**Mutation testing found 16 survivors, in three groups:**
- **Equivalent on this data (5).**
  - Two touched the overflow bucket, which no generated value ever reaches. A direct test of `latencies` with overflowing values now catches both.
  - Two were `zip(strict=False)` with the argument removed or set to `None`, which is truly equivalent. The line no longer uses `zip`.
  - One changed `range(5, 120, 15)` to `121`, which yields the same values. It's now written as eight steps, so changing the count moves a log outside the window, and validation fails.
- **Untested behaviour (10).** These were `mkdir`'s `parents` and `exist_ok` flags, the `--root` default and the help text. New tests write into a nested new folder twice, run with no arguments, and run with `--help`.
- **Hidden by macOS (1).** Changing `scenarios` to `SCENARIOS` survived, because macOS paths ignore case. The test now compares the folder's name exactly.

## 6. Test

`make check` passes with 963 tests, and 1 skipped because the network test only runs in CI. CI on Linux reproduced the committed bytes, which were generated on macOS.

**Limits:**
- **Reproducibility assumes the same platform maths.** Draws pass through `math.log`, `exp`, `cos` and `sin`, which can differ in the last bit across platforms. Values are only bucketed or rounded, so a flip would need a draw within one bit of a boundary. If CI ever disagrees, the drift test fails rather than letting the files go silently wrong.
- **Generator version and seed aren't recorded in the files yet.** §14.4 puts them in the benchmark manifest, which is M6.
- **One case only.** T2.3 adds the contrasting dependency case and the unanswerable one. T2.4 tests what an investigator could learn from names and text.
