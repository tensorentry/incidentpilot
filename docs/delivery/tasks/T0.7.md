# T0.7 — Owner isolation

**Milestone:** M0 Foundation · **Issue:** IP3-001 · **Status:** done

Added after T1.3, when you asked for each incident to be isolated by tenant end to end. You chose owner-level isolation over incident-level on 2026-11-08.

## 1. Understand

- Spec refs: §1.4 (multi-tenant hosting is a non-goal), §3.3, §7.2, §7.3, §8.1 (owner is never model-writable), §12.4 (route-level checks), §15.4 (tenant isolation required before any external exposure).
- Errata touched: E7 (snapshots), E9 (closing an attempt), E10 (seeded owner), E11 (admission), E14 (evidence dedup).
- **Already designed:** incident isolation. Each investigation has a frozen snapshot, scoped evidence grants and its own budget.
- **Not designed:** owner isolation. It relied on route checks, most tables had no owner, evidence and snapshots were shared across owners, and only one owner existed.

## 2. Plan

Write erratum E19 and ADR-014, and add the work to the tracker. Docs only. Code arrives with the tasks that build each table.

## 3. Validate plan

- **Timing:** no tables exist yet, so this is a doc change now. After M3 it would mean migrating every table. It must land before T1.4, because it changes how evidence is identified.
- **Scope kept narrow:** isolation inside one local installation. Public hosting stays excluded by §1.4. Per-owner limits and real authentication are deferred.
- **Known traps in PostgreSQL row-level security, each closed by a rule in E19:**

| Trap | Rule |
|---|---|
| Superusers, `BYPASSRLS` roles and table owners skip policies | Runtime roles are none of these, and the policy is forced |
| An unset setting reads back as `''` after a transaction ends | `NULLIF`, so an unset owner sees nothing |
| A pooled connection could keep the previous owner | `SET LOCAL` per transaction |
| Unique constraints ignore policies and can reveal a row exists | Every unique key includes `owner_id` |
| Views run with their creator's rights | `security_invoker = true` |
| The scheduler has to see every owner | Five definer functions that return only IDs and counts |

## 5. Validate implementation

**Two wrong references, fixed.** I'd cited §1.3 for the non-goals and §9.2 for the model-writable rule. They're §1.4 and §8.1. A script checked every section, table and task ID named in E19 and ADR-014 against the spec, the errata and the tracker. Those two were the only failures.

**Gaps that belong to later tasks:**
- The sweeper finds expired leases across owners, then closes each under its owner. A worker could renew between those two steps, so the sweeper has to recheck the lease under the row lock. That's D08's existing rule, applied in T3.10.
- Evaluation runs in M6 need an owner. A dedicated evaluation owner is the obvious choice, decided there.
