# T4.6 — Bounded briefing builder

**Milestone:** M4 First live agent · **Spec:** §5.3 (D07), §6.3, §8.5 (D12), §9.1 · **Errata:** E3, E15 · **Status:** done

## 1. Understand

- **Spec refs:**
  - **§9.1:** the model sees the incident, the authorized service graph, the current evidence briefing, the tool descriptions, the deadlines and the response schema, never the oracle. The briefing is "bounded by estimated tokens" and prefers "salient, source-referenced structured observations rather than pasting all logs".
  - **D07:** each turn starts from the frozen incident and the committed evidence briefing.
  - **§6.3:** after a crash between an evidence commit and the model seeing it, recovery rebuilds the briefing from committed evidence, never from SDK state.
  - **D12:** evidence reaches the model through a typed selector into a bounded briefing.
  - **E3:** citations use one structured selector.
- **Already in place:**
  - Visible evidence checked against its digests (T3.11).
  - The frozen scope and service graph (T4.3, T4.4).
  - The budget counters (T3.11, T4.3).
  - A token bound from bytes (T4.5).

## 2. Plan

- **`model_runtime/briefing.py`:**
  - `build_briefing`: pure. It takes the incident, the scope, what's left of the budget and the visible evidence, and returns JSON text within a token budget, plus what it showed and what it left out.
  - `load_briefing`: reads all of that from the database for a lease.
- **The gateway's `selector` moves to `domain/evidence.py` as `whole_selector`**, so the briefing and the gateway cite rows the same way.

**Acceptance:**
- A briefing never exceeds its budget.
- Every record it shows carries the selector that cites it.
- It says how many records of each kind it left out.
- A recovery attempt gets the same evidence its predecessor committed.

## 3. Validate plan

| Rule | How |
|---|---|
| Durable state only (§6.3, D07) | `load_briefing` reads the incident, scope, counters and visible evidence. Nothing comes from the SDK or process memory. A test briefs a recovery attempt and gets the same evidence |
| Bounded by estimated tokens (§9.1) | The briefing is ASCII JSON, so its length is its bytes, an upper bound on byte-level BPE tokens (T4.5). It keeps room for the largest possible omitted counts, so the final text is never over budget |
| Source-referenced (§9.1, D12, E3) | Each record carries its selector, its source reference and its content |
| No oracle (§9.1) | The inputs are the incident, the scope, the counters and the evidence. The oracle has no route into any of them (T2.1) |
| Deterministic | Services, per-tool counts and evidence have fixed orders, so the same state gives the same text |

**Decisions:**
- **Evidence appears exactly as committed.** The briefing doesn't summarize series or group logs. A derived number would be a claim nothing stored, and the model could cite it. Computation belongs to the validator.
- **Whole records are left out, never cut.** Kinds go by priority: deployments, span summaries, series, then logs. Rare and decisive kinds go first, the most numerous last. Within a kind the newest stay, since they follow the model's latest line of inquiry. A smaller record can still fit after a larger one didn't.
- **What's shown stays in commit order,** so the model reads it chronologically.
- **Left-out records are counted by kind.** The model knows it isn't seeing everything, and can query again within its quota.
- **"Remaining" counts reservations, not dispatches.** A reserved call is spent from the model's point of view.

## 5. Validate implementation

**Found while testing:**
- **Span summaries need a window**, like series. The first test factory gave a window only to series.
- **A recovery attempt's claim waited out the retry backoff.** The recovery test now sweeps with no backoff, as the recovery tests do.
- **The first draft wrote UTF-8 JSON with `ensure_ascii=False`.** Like the gate in T4.5, it now writes plain ASCII JSON. That is one less parameter, the length is the byte count, and the model reads JSON escapes as easily.
- **The size check is conservative by design.** It keeps room for the largest possible omitted counts, so a budget can't be filled to the exact byte. Tests that compared against the shown text alone failed, and now compare against what the check counts.

**Planted faults.** 18 were planted one at a time:

| Fault | Caught by |
|---|---|
| Budget exceeded by one | the exact budget test |
| Comma between records not counted | the exact budget test |
| No room kept for the omitted counts | the never-over-budget test |
| Oldest kept within a kind | the newest-stay test |
| Kind priority ignored | both priority tests |
| Stops at the first record that doesn't fit | the smaller-record test |
| Shown in priority order, not commit order | the commit order test, among 6 |
| Omitted counts not stated | the never-over-budget test |
| Selector missing | the as-committed test, among 3 |
| Services unsorted | the header test |
| Header over budget allowed | the header refusal test |
| JSON separators widened | the ASCII and exact budget tests |
| Per-tool counts unsorted | the name order test |
| Tool calls counted when dispatched | the reserved-calls test |
| Model requests counted when dispatched | the reserved-calls test |
| Per-tool calls counted when dispatched | the reserved-calls test |
| Seconds not floored at zero | the passed-deadline test |
| Scope services cut short | the fresh-investigation test |

The first round missed three:
- **Off by one and the uncounted comma.** Both hid inside the slack the conservative check leaves, so a test now pins the smallest budget that shows two records to exactly what the check counts.
- **Per-tool counts unsorted.** Dict equality ignores order. Order matters here, because quota rows come back from the database in no fixed order and a recovery attempt must rebuild the same text. A test now checks the key order.

The loader's three "counted when dispatched" faults needed a reserved-but-unsent call to tell them apart. The test that spent budget through the gateway dispatched everything it reserved.

**Mutation testing.**
- **The first run aborted before it began.** mutmut's unmutated test run failed, because I was running another worktree's database tests at the same time. Every scratch database is copied from one shared template, and PostgreSQL refuses a copy while another session holds the template. Nothing was wrong with the code. The run was restarted with nothing else touching the database.
- **One survivor:** `used > budget_tokens` against `>=` for the header. No test had a header that exactly fills the budget. A test now does, and the mutant, re-run alone with it, was killed.

**Limits:**
- Nothing calls `load_briefing` yet. The runner sends it as the model's input at T4.7.
- One large record can crowd out several small ones of a lower kind. Priority is by kind, not by size.
- The budget is in estimated tokens, from bytes. The real tokenizer's count is lower.
