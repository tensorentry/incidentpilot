# T4.4 — Remaining four tools

**Milestone:** M4 First live agent · **Spec:** §8.1, §8.3, §8.4 (D11) · **Errata:** E13, E15, E16, E20 (new) · **Status:** done

## 1. Understand

- **Spec refs:**
  - **§8.1** lists the P0 tools and their model-writable arguments:
    - `search_logs`: service, window, a constrained filter and severity, limit and cursor;
    - `get_deployments`: service, window, limit and cursor;
    - `get_dependency_health`: an *authorized* dependency, window and metrics;
    - `get_trace_summary`: service, window, "allowed trace IDs" and limit.
  - **E16** makes `get_trace_summary` the fifth P0 tool.
  - **§8.3:** a log filter is literal, with no query language.
  - **D11:** scope is checked before anything is reserved.
  - **E13:** each tool has its own quota row.
  - **E15:** a span summary is the unit of trace evidence.
- **Already in place:**
  - The queries and all five source methods (T4.2).
  - The gateway, the ledger and `get_service_metrics` (T4.3).

## 2. Plan

- **`tools/catalog.py`:** the four tools, sharing one helper that builds the query and passes it to the gateway.
- **`ToolGateway.call(provider_call_id, query)`:** the gateway works out the tool, the source method and what the query reaches from the query itself.
- **`load_scope`** also reads the snapshot's service graph, so the gateway can check a dependency before reserving anything.
- **Erratum E20:** the trace tool's arguments.

**Acceptance:**
- Each tool asks its own source method with exactly the model's arguments.
- Each tool commits the evidence it shows and spends only its own quota.
- A dependency outside the graph costs nothing.
- The five schemas hold only model-writable arguments, and nothing else is registered.

## 3. Validate plan

| Rule | How |
|---|---|
| Scope checked before any reservation (D11) | Every service the query names must be in the frozen `allowed_services`. A dependency must also be an edge of the snapshot's service graph, and the window must lie inside the frozen window. A refusal is `OUT_OF_SCOPE`, with no row, no quota and no source call |
| What the scope check sees is what the source gets | `call` takes only the query. The tool name, the services, the edge and the window all come from it, so a tool can't send the check one service and the source another |
| Each tool has its own quota (E13) | The tool name comes from the query's type. Tests check that a call spends exactly its own tool's row, and that a spent quota for one tool leaves the others working |
| Context not model-writable (§8.1) | Each schema is strict, lists exactly its arguments, and names nothing trusted: owner, investigation, attempt, epoch, snapshot, budget or lease |
| Literal log filter (§8.3) | `contains` stays a substring match, 1 to 100 characters, as T4.2 built it |
| Honest trace coverage (E16) | A window that summaries only partly cover is `partial`, even with records |

**Decisions:**
- **An "authorized dependency" is an edge of the snapshot's service graph** whose two ends are both in scope. The graph is frozen with the snapshot, so the check needs no adapter call. The adapter keeps its own check, so a different source can't skip it.
- **The trace tool takes no trace IDs (E20).** Summaries have no trace ID, and the fixtures hold no single traces. An argument no source can honour would be ignored or always refused.
- **Severity is text in the schema,** and its description lists the values. The query validates it, so a bad value gets the same free `INVALID_ARGUMENT` answer as any other bad argument.
- **Optional arguments are nullable and required.** The strict schema needs every property, so the model passes `null` for no filter or no cursor.

## 5. Validate implementation

**Found while testing:**
- **A trace query over the whole observed window answered `partial`.** The summaries cover 17:30–18:00 and 18:15–18:45 of 17:00–19:00, so `partial` is the honest answer. The happy-path case now uses the incident window, which a summary covers completely, and a separate test pins `partial`.
- **Two turns in the same attempt reused the provider call ID `call-1`** and hit the unique key on `(attempt_id, invocation_id)`. This is T4.3's documented limit. The tests now number calls across turns.

**Planted faults.** 14 were planted one at a time:

| Fault | Caught by |
|---|---|
| Dependency edge not checked | the dependency scope test |
| Dependency not checked against the services | the dependency scope test |
| Window not checked | both scope tests |
| Logs recorded as another tool | the per-tool, paging and quota tests |
| Dependency asked as service metrics | the per-tool test |
| Graph loaded without its edges | the dependency scope, per-tool and quota tests |
| Log filter dropped | the per-tool and argument tests |
| Log cursor dropped | the paging and cursor tests |
| Deployment cursor dropped | the cursor test |
| Trace cursor dropped | the cursor test |
| Dependency sides swapped | the dependency scope, per-tool and quota tests |
| Trace tool builds a deployments query | the per-tool and trace coverage tests |
| Trace tool not registered | the registration test |
| A trusted argument in a schema | the schema test |

The first round missed the trace cursor. The deployment cursor was caught only because a malformed cursor happened to fail validation. A test now gives each paged tool a cursor from another query, and checks that the source receives it and refuses it.

**Mutation testing.**
- **The first run was discarded.** Docker Desktop stopped partway through, which took PostgreSQL down. mutmut reported 5128/5128 killed, but a mutant whose tests fail to connect counts as killed, so the number meant nothing. The script's next phase caught it, because its unmutated test run failed. Docker was restarted, a watch was added that stops the run if Docker goes down, and everything ran again.
- **The second run** killed 5121 of 5128. The 7 timeouts were in evidence visibility and idempotent replay, code this task doesn't touch. Each was re-run alone and killed.
