# T4.7 — InvestigatorRunner and prompt

**Milestone:** M4 First live agent · **Spec:** §9.1, §9.2, §5.3 (D07), §11.3 · **Errata:** E2, E3, E4, E5 (amended) · **Status:** done

## 1. Understand

- **Spec refs:**
  - **§9.1:** an `InvestigatorRunner` shields the system from SDK types and failures and returns `CandidateOrStop`. The model gets the incident, the service graph, the briefing, the tool descriptions, the deadlines and the response schema.
  - **§9.2:** the versioned prompt policy covers role, goal, tools, observations, evidence, causality, security, actions, stop and output.
  - **D07:** the model selects a tool or finishes, while budget remains.
  - **§11.3:** diagnostics stop at the finalization reserve boundary, so a fallback can still be published.
  - **E5:** `Stop(reason, detail)`, where the application writes the detail.
- **Already in place:**
  - The SDK settings and the mapping from SDK endings to stop reasons (T4.1).
  - The tools and their gateway (T4.3, T4.4).
  - The call gate (T4.5).
  - The briefing (T4.6).

## 2. Plan

- **`model_runtime/prompt.py`:** the instructions, a version and a digest over both.
- **`model_runtime/runner.py`:** `InvestigatorRunner.investigate(connection, lease, keeper)`:
  1. Stop at once if only the reserve is left.
  2. Load the briefing and scope.
  3. Build an agent with the instructions, the gated model, the five tools and the candidate output type.
  4. Run it with the briefing as input, a turn limit, and a clock that runs out at the reserve boundary.
  5. Return the candidate, or a `Stop` naming why there is none.
- **E5 amended:** a budget stop names the limit that ended the run.

**Acceptance:**
- A run sends the instructions and the committed briefing, and every request and tool call passes its gate.
- Each ending without a candidate is a typed `Stop` with an application-written detail.
- A lost lease, a tool's failure and unrecognised errors are raised.

## 3. Validate plan

| Rule | How |
|---|---|
| The runner shields the system from the SDK (§9.1) | `investigate` returns only `ReportCandidate` or `Stop`. SDK endings map through `stop_reason` (T4.1) |
| Every request reserves first (§11.1, D14) | The agent's model is a `GatedModel` built for this lease. A test checks both requests settled in the ledger |
| Every tool goes through the gateway (§8.1) | The tools come from the catalog, with a `ToolGateway` as the run's context |
| The briefing is durable state (§6.3) | The input is `load_briefing`'s text, compared in a test with a briefing loaded separately |
| Diagnostics stop at the reserve (§11.3) | No run starts inside the reserve. A running one is cut off when only the reserve is left, measured on the database clock |
| The detail is application text (E5) | `DETAILS` holds one fixed sentence per reason, and a test checks every reason has one |
| Prompt versioned (§9.2) | `PROMPT_SHA256` covers the version and the text, and a test pins it |
| Untrusted tool text (§9.2) | The instructions say so, and a test checks the rule is there |

**Decisions:**
- **Time endings are named for the limit.** E5 lists four reasons. The runner's own clock and a ledger refusal past the deadline are time limits, and `TerminationReason` already tells them apart. So `Stop` gains `deadline_reached` and `finalization_reserve_reached`, both from that list, and E5 records the change.
- **Only the clock's own expiry counts as the reserve.** A `TimeoutError` from anywhere else, such as a socket, is raised, so a failure isn't hidden as a normal stop.
- **The runner doesn't choose the query window.** It's frozen when the investigation starts. The live run (T4.10) starts each investigation over the snapshot's observation window, so the lead-up to the incident is in scope. T4.4 deferred this question here.
- **Wiring into a worker job is T4.8.** A `Stop` needs the fallback that T4.8 builds, so the job lands with it.

## 5. Validate implementation

**Found while testing:**
- **The SDK wraps a text input in a user message.** The test reads the content from that message.
- **A briefing's seconds tick between two loads.** The test compares briefings without that one field.
- **A `deadline_reached` test pinned E5's original four reasons.** It now uses `cancelled`, which stays the application's decision, never the runner's.

**Planted faults.** 15 were planted one at a time. 14 were caught on the first round:

| Fault | Caught by |
|---|---|
| A run starts inside the reserve | the reserve cut-off test |
| No clock on the run | the reserve cut-off test |
| Clock counts to the deadline, not the reserve | both reserve tests |
| Any timeout read as the reserve | the unrecognised-failure test |
| Deadline reported as budget | the typed-stop test |
| Instructions not sent | the full-run test |
| Model ungated | five tests |
| No output schema | the full-run and typed-stop tests |
| Tools not registered | the full-run and typed-stop tests |
| Briefing not sent | the full-run test |
| Turn limit ignored | the typed-stop test |
| Unrecognised failures swallowed | the unrecognised-failure and typed-stop tests |
| Security rule dropped from the prompt | the prompt pin and rule tests |
| Digest ignores the prompt version | the digest tests |

The fifteenth removed the runner's opening `keeper.require()`, and nothing failed. It changed nothing: the gated model checks the keeper before any write, so a lost lease is still raised before the first request. The line is gone.

**Mutation testing.** The first run left 5 survivors in the runner, and was stopped once they were understood:
- **The run config was never shown to matter.** It makes tool calls from one response run one at a time on the worker's single connection. A test now has one response ask for three tools. Without the run config, they start together and collide on the connection: "an owner transaction can't start inside another transaction".
- **Agent-level model settings duplicated the run config's,** so removing them changed nothing. They're gone.
- **The agent's name** changed nothing either, because nothing reads it with tracing off (2 mutants). It's now a module constant, which mutmut doesn't mutate. This is an equivalent mutant, not a gap in the tests.

A targeted run then killed 106 of the 108 runner and prompt mutants. The other two crashed the test process:
- **Both dropped the gated model.** The SDK then fell back to its default provider and tried the network. On macOS, the OS proxy lookup crashes in a forked process, as in T4.1.
- **The integration tests had no guard against the network**, unlike the SDK tests. `tests/integration/conftest.py` now sets `no_proxy`, and refuses name lookups for anything but the local database host. With the guard, those mutants fail cleanly, and no integration test can reach a model provider.

The full run caught everything:

| Target | Result |
|---|---|
| `mutmut` | 5666/5666 killed |
| State edges | 124/124 caught |
| Enum values | 149/149 caught |
| Decorated functions | 164/164 caught |

The planted faults were re-run against the final code, and all 14 are still caught.
