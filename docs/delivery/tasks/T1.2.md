# T1.2 — State machines

**Milestone:** M1 Contracts · **Issue:** IP3-002 · **Status:** done

## 1. Understand

- Spec refs: D06 and §5.2 (investigation), §6.1 (attempt), invariants 1 and 7 in §3.3.
- Errata: E1 adds `VALIDATING → RETRY_WAIT`.
- Every later state change goes through these rules, so a wrong edge here would spread everywhere.

## 2. Plan

Add `src/incidentpilot/domain/transitions.py` with two immutable tables and a check that raises on an illegal change, tests first.

## 3. Validate plan

- **Independent truth:** tests read legal edges from the corrected D06 in `docs/spec-errata.md`, so a typo in the table can't confirm itself. Attempts have no diagram, so their four edges come from §6.1 and are written out in the test.
- **Exhaustive:** all 49 investigation pairs and all 25 attempt pairs.
- **Graph properties:** every status reachable from `QUEUED`, no dead ends, and both leased statuses can recover.

**Out of scope:**
- Whether a change is allowed right now, such as a retry with attempts left, needs data. Callers decide that.
- Cancelling twice returning `200` (§12.1) is API behaviour, so `CANCELLED → CANCELLED` stays illegal here.
- Which attempt status pairs with which investigation change belongs to `close_attempt` (E9, T3.10).

## 5. Validate implementation

**A real weakness, fixed.** `StrEnum` members equal plain strings, so `AttemptStatus.RUNNING == InvestigationStatus.RUNNING` is true, and the wrong type passed the table lookup at runtime. mypy catches this in typed code, but database rows are untyped, so it wouldn't help at that boundary. The check now raises `TypeError` unless both values are the exact status type.

**A flaw in the mutation harness, found and fixed.** A mutation to attempt code was reported as caught by a test about investigations, which is impossible. The likely cause is stale bytecode: Python reuses a `.pyc` when file size and modification second match, so a same-sized mutation could run the previous mutation's code and report a false catch. The harness now disables bytecode, purges caches and checks that the expected test is the one that failed. All earlier mutations were rerun.

**Mutation results,** from a green baseline of 183 tests:

| Target | Mutations | Result |

| `transitions.py` logic | 9 | All caught by the expected test |

| `settings.py` and `.env.example` (T0.3) | 12 | All caught by the expected test |

Removing an enum member fails at import, because other code references it. Those two `enums.py` mutations are caught at collection, not by their contract test.

mypy also rejects a wrong enum or raw strings passed to the checks.
