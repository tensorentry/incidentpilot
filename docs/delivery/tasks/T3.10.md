# T3.10 — Sweeper, LOST, recovery and the shared terminal transition

**Milestone:** M3 Durable slice · **Issue:** IP3-004 · **Status:** done

## 1. Understand

- Spec refs:
  - D08: the sweeper locks the investigation, finds the lease expired, marks the attempt `LOST`, releases capacity and moves to retry wait. Another worker claims the recovery at the next epoch, and the stale worker's commit is rejected.
  - §6.3 crash matrix: after a claim, before the provider call, "the lease eventually expires and the attempt is replaced".
  - §6.4 D09: cancellation locks the row; whichever of cancel and publication commits first wins.
  - §2.4: 2 recovery attempts; a 10-minute maximum queue age; a deadline 180 s from first claim. §3.2: retry never resets the deadline or budget.
  - §6.6: the worker or sweeper owns attempt replacement, with at most two additional attempts.
- Errata:
  - **E9:** one function, `close_attempt`, run in the caller's transaction under the investigation row lock, used by publication, cancellation, the sweeper and failure handling. It sets the attempt's final status, releases the slot, settles the ledger, and appends the event.
  - **E1:** `VALIDATING → RETRY_WAIT` when the lease is lost during validation.
  - **E19:** expired-lease discovery is one of the five scheduler functions; the sweeper finds work across owners and closes each under its owner.

## 2. Plan

- **Migration `0006`:** `sweepable_investigation(max_queue_age)`, a scheduler function that locks, with `SKIP LOCKED`, one investigation that is RUNNING or VALIDATING with an expired lease, QUEUED beyond the queue age, or RETRY_WAIT past its deadline. It returns only the owner and ID.
- **`workflows/recovery.py`:**
  - `close_attempt(connection, attempt, status, failure)`: final status and failure category, end time, slot released, and `ATTEMPT_LOST` or `ATTEMPT_FAILED` appended. It reads the investigation from the attempt row, so a caller can't pair an attempt with the wrong investigation.
  - `end_investigation`: a terminal status with its termination reason, no current attempt, and the matching event.
  - `sweep_once` and `sweep(limit)`. An expired lease becomes `LOST`, then a retry with a short backoff, unless the deadline has passed (`deadline_reached`) or both recovery attempts are spent (`retries_exhausted`). Old queued work fails with `queue_age_exceeded`; an overdue retry wait fails with `deadline_reached`.
- **`application/investigations.cancel_investigation`:** under the row lock, closes any attempt as `CANCELLED` and ends the investigation `CANCELLED`. Cancelling twice is fine; cancelling ended work raises `Conflict`. Exposed as `incidentpilot cancel-investigation`.

**Acceptance:** a crashed worker's job is recovered by another worker at the next epoch; the crashed worker can't commit; recovery stops after two retries or at the deadline.

## 3. Validate plan

| Rule | How it holds |
|---|---|
| One shared closing function (E9) | `close_attempt` is used by the sweeper and cancellation now, and by publication in T3.12 |
| Caller's transaction, under the row lock (E9) | It never opens a transaction. Both callers lock the investigation row first |
| `LOST` doesn't claim anything about billing (§6.1) | `LOST` records only that the lease was reclaimed, with failure category `LEASE_LOST` |
| Stale worker can't commit (D08) | After `LOST`, the investigation leaves `RUNNING` and has no current attempt, so the fence rejects the old lease. A test shows it |
| Next attempt at the next epoch (D08) | The claim bumps the epoch. A recovered claim gets epoch 2 and a new attempt |
| Two recovery attempts (§2.4) | With 2 attempts started the sweeper retries; with 3 it fails `retries_exhausted` |
| Deadline never reset (§3.2) | A loss past the deadline fails `deadline_reached`, and a retry wait past the deadline fails too |
| Queue age 10 minutes (§2.4) | An 11-minute-old queued investigation fails `queue_age_exceeded`, and a fresh one stays queued |
| `VALIDATING → RETRY_WAIT` (E1) | Covered by the parametrized expired-lease test |
| Cross-owner discovery, closed under its owner (E19) | The sweeper adopts the found row's owner, and the events land under owner B |
| Cancel vs publish decided by the row lock (D09) | `cancel_investigation` locks the row before deciding. The race with publication is tested once publication exists (T3.12) |

**Deviations and decisions:**
- **One discovery function, not one per case.** E19 names "expired-lease discovery" among exactly five functions. Queue age and overdue retry waits are found by the same function, because all three are the sweeper finding work nobody else will end. It still returns only an owner and an ID.
- **A 2-second backoff before a recovery may be claimed,** so a flapping worker doesn't burn both retries at once. §6.6 asks for bounded backoff; the value is mine.
- **E9's ledger steps aren't here yet:** moving model calls to `UNKNOWN` or `FAILED` and keeping or releasing tool reservations. The `model_calls` and `tool_calls` tables arrive with the ledger (T4.5 and M5), and `close_attempt` grows those steps there.
- **A success or cancellation appends no attempt event of its own.** `REPORT_PUBLISHED` or `INVESTIGATION_CANCELLED` records it. The enum has no attempt-success event, and adding one would duplicate the terminal event.

## 5. Validate implementation

**Planted faults in `sweepable_investigation`:**

| Fault | Caught by |
|---|---|
| Expired leases never found | Nine tests |
| Queue age ignored | The queue-age and sweep-limit tests |
| Overdue retry waits ignored | `test_a_retry_wait_past_its_deadline_fails` |
| `FOR UPDATE` without `SKIP LOCKED` | `test_a_locked_investigation_is_skipped_by_the_sweeper` |

**End to end:** a worker whose maintenance runs the sweeper picks up a "crashed" worker's expired job, retries it and runs it at epoch 2.

**Mutation testing** found five survivors on the first run:
- **The sweep pass's results weren't checked:** appending `None` instead of the swept record went unnoticed. The test now checks each record's investigation, status and reason.
- **`close_attempt` took the investigation ID but used it only for loss and failure events,** so cancellation passing no ID went unnoticed. It now reads the investigation from the attempt row, which removes a parameter a caller could get wrong.
- **Three were equivalent:** two case flips of SQL, and a default limit of 51 instead of 50. The query and the limit are module constants now.

## 6. Test

- `make check` passes offline with 1380 unit tests, and 1 skipped because the network test only runs in CI.
- `make test-integration` passes with 199 tests: 21 for recovery and the sweeper, 6 for cancellation, and 1 for the `cancel-investigation` command.
- 16 four-way parallel runs of the integration suite all passed.

**Limits:**
- **A job that raises still waits out its lease.** The worker logs it, and the sweeper recovers it after expiry. Closing the attempt at once needs a failure category from the job, which the investigator runner supplies in M4.
- **Cancellation doesn't stop a job already running in-process.** It fences the worker out, so the worker's next fenced write or renewal fails. A cancellation flag checked at dispatch (D09) comes with the gateway in M4.
