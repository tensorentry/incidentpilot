# T3.11 — Scripted fake model with real fenced writes

**Milestone:** M3 Durable slice · **Issue:** IP3-004 · **Status:** done

## 1. Understand

- Spec refs:
  - §17.1 and Phase 1: the durable slice runs with a fake model, but its writes must be real, so recovery is tested against real rows.
  - §7.2: `model_calls`, `evidence` and `investigation_evidence`. §7.3: evidence is sanitized and immutable, deduplicated by content and source identity together, and reused across attempts only through visibility rows. The runtime role shouldn't be able to change it.
  - §11.1 and D14: the budget lives on the investigation. A request is reserved before dispatch, then settled, failed or left `UNKNOWN`. A request that may have reached the provider keeps a conservative reservation.
- Errata:
  - **E9:** `close_attempt` moves `DISPATCHED` calls to `UNKNOWN` and `RESERVED` calls to `FAILED`. `DISPATCHED` commits before the request is sent, so `RESERVED` proves it never was. `UNKNOWN` is final.
  - **E18:** each change has one effect on the reservation: hold, release, settle or retain. `dispatched_at` records which calls were sent, so the counters can be recomputed from the rows.
  - **E14:** a unique evidence identity, inserted with `ON CONFLICT DO NOTHING`, read back, then granted, all inside the fenced transaction.
  - **E15:** one evidence row per citable source record. **E19:** the identity includes the owner.
- Risk 3 in the plan: a fake slice that skipped the evidence and ledger writes would pass Phase 1 without proving recovery.

## 2. Plan

- **Migration `0007`:**
  - Ledger counters on `investigations`: requests reserved, dispatched, settled and unknown; cost reserved, known and unknown; actual input and output tokens. CHECKs keep them nonnegative, ordered, and within the request limit.
  - `model_calls`, with E18's states and `dispatched_at`. CHECKs tie the timestamps, usage and failure category to the state.
  - `evidence` with the E14/E19 identity, and `investigation_evidence` for visibility. The runtime role may only read and insert both.
- **`persistence/ledger.py`:**
  - `reserve_call` checks the request limit, the spend cap and the deadline in one guarded `UPDATE`. A denial raises `BudgetDenied`.
  - `dispatch_call`, `settle_call`, `fail_call` and `mark_call_unknown` all go through one `_move`. It locks the call, checks the change against the T1.3 transition table, and applies `counter_changes`, which turns each E18 effect into counter changes. Then it appends the event.
  - `close_calls` handles E9's ledger steps for a closing attempt.
- **`persistence/evidence.py`:** `commit_evidence` sanitizes the content, keys included, and the source reference, then hashes and inserts, reads the ID back, and grants visibility. It appends `EVIDENCE_COMMITTED` only when the investigation gains a row. `visible_evidence` reads rows back and checks their digests.
- **`domain/evidence.EvidenceDraft`:** a source record before committing. It has no ID, owner, snapshot, redaction version or digest, because committing decides those.
- **`workflows/scripted.py`:** `ScriptedModel`, a worker `Job`. Each step runs three fenced transactions in order: reserve, dispatch, then settle together with the step's evidence. Planted faults strike once per instance: a crash after reserving, a crash after dispatching, or a provider error.
- **`close_attempt`** calls `close_calls`.

**Acceptance:** a worker that crashes mid-script leaves real ledger rows; the sweeper closes them by E9; a second worker resumes at the next epoch, reusing the lost attempt's evidence and carrying its budget forward. The counters always equal a recount of the rows.

## 3. Validate plan

| Rule | How it holds |
|---|---|
| Budget on the investigation, not the attempt (§11.1) | Counters live on `investigations`. A test shows the recovery attempt's totals include the lost attempt's calls |
| Reserve before dispatch (§11.1, D14) | `reserve_call` checks the limit and inserts the call in one fenced transaction, before any dispatch |
| `DISPATCHED` commits before sending (E9) | The scripted model commits dispatch in its own transaction, then "sends" |
| `RESERVED` → `FAILED` releases; anything sent retains (E18) | `counter_changes` follows `model_call_effect` from T1.3. A unit test checks every legal change, and integration tests check each against the rows |
| `UNKNOWN` is final (E9) | The transition table refuses it. A test has a stale worker's late settlement refused by the fence, and again by the state check with the fence bypassed |
| Counters recomputable from rows (E18) | Every counter check in the tests recounts the rows from `dispatched_at` and states, and compares |
| `close_attempt` handles the ledger (E9) | It closes open calls after releasing the slot. Tests cover loss, cancellation and the sweeper |
| Evidence sanitized before persisting (§7.3, §15.1) | Content, keys and source reference pass the sanitizer before hashing. A canary in each place is stored redacted |
| Dedup identity includes content and source (§7.3, E14) | A unique constraint over owner, snapshot, kind, source reference, adapter version, redaction version and digest. A test changes each part in turn |
| Insert, read back, grant, all fenced (E14) | One function inside the caller's fenced transaction. A stale lease writes nothing, and a concurrent identical insert waits, then reuses the row |
| Reuse across attempts only through visibility (§7.3) | Recommitting in a recovery attempt finds the row already granted. `first_attempt_id` keeps the attempt that first committed it |
| Owner and snapshot never from the caller (E19) | Both come from the investigation row and the row-security context. A test with two snapshots shows each row takes its investigation's snapshot |
| Runtime role can't change evidence or delete calls (§7.3) | Grants are `SELECT, INSERT` on evidence and visibility, and no `DELETE` on calls. Tests confirm |

**Deviations and decisions:**
- **Model calls arrive here, not at T4.5.** T3.10 put them with the provider gate, but the plan's risk 3 needs real ledger rows now. T4.5 keeps the gate itself: the provider client, estimates from the pricing table, and the finalization reserve.
- **No finalization reserve check yet.** `reserve_call` refuses past the deadline but doesn't hold back the last 15 seconds for finalization. That needs a diagnostic-or-finalization purpose on each call, which comes with the runner (T4.5 and T4.7).
- **The spend cap is checked only when reserving.** A settlement whose actual cost exceeds its estimate is recorded as it is, even if that takes the total past the cap. Refusing it would lose real usage, and §11.1 already says an exact dollar ceiling can't be promised.
- **Tool calls and `tool_evidence` wait for the gateway (T4.3).** The scripted model commits each step's evidence directly, where the gateway will commit what its tools return.
- **Evidence visibility has one reason so far,** `tool_result`, the only way evidence arrives.
- **`EVIDENCE_COMMITTED` is appended only when visibility is new,** so a recovery that refetches what it can already see adds no event. The payload's `reused` says whether the row already existed.
- **The worker entry point moves to T3.13.** T3.9's record expected it here, but a process needs a script built from a snapshot, and the kill/restart demo is what needs one.

## 5. Validate implementation

**Planted SQL faults.** Mutation testing doesn't reach module-level SQL, so 30 faults were planted one at a time, covering:
- each `reserve_call` limit and each term of the spend sum;
- the call's attempt filter and row lock;
- the deadline check behind a denial;
- the states `close_calls` picks up;
- the columns a move writes;
- every column of the evidence lookup;
- both `ON CONFLICT` clauses;
- the visibility filter;
- the snapshot lookup.

The first run had problems:
- **Six faults were "caught" for the wrong reason.** psycopg sends strings untyped, so `%s IS NOT NULL` was a SQL error rather than the fault I meant. They were replanted as `%s::text IS NOT NULL`.
- **Two then survived:**
  - **The lookup ignored `kind`:** no test had two records that differed only in kind. A test was added.
  - **The lookup ignored the redaction version:** every test row had the current version. A new test re-labels a stored row as older and checks it isn't reused.
- **The `kind` fault still survived the new test, by luck of row order:** the lookup happened to return the newer row. The identity test now commits in both orders and checks every commit's ID.

All 30 are now caught.

**Other findings:**
- **Existing test bug:** the catalog vocabulary check matched the first CHECK mentioning `state = ANY`. On `model_calls` that's the ended-when-final rule, so the pattern is now anchored to the start of the definition.
- **Redundant lock removed:** `close_calls` listed open calls `FOR UPDATE`, which every caller's investigation lock already covers. `_move` keeps the call's own row lock, and a test shows that lock stops a caller outside the fence from moving a call twice.

**Mutation testing** found 25 survivors on the first run:
- **Seventeen were messages no test pinned down:**
  - error texts matched only in part;
  - the budget-stop log line;
  - a denial built without its investigation ID;
  - the planted crash messages.

  The tests now match each message whole, and check the log line. The provider error no longer has a message, since the script catches it at once.
- **A provider error's failure category went unchecked:** passing none instead of `PROVIDER_ERROR` was allowed, because a cancelled attempt's calls also fail without one. The test now checks the category.
- **A zero estimate was untested,** so refusing estimates `<= 0` went unnoticed. The test now reserves a free request and sees it counted.
- **The evidence commit's missing-investigation error can't happen,** because the fence holds that row locked. It is an assertion now, like the other impossible cases.
- **Three were equivalent, so the code was restructured:**
  - **Settle-only usage guard:** `_move` passed usage only for settling, but the callers already did that, so it now passes usage straight through.
  - **Counter-update SQL:** a case flip of the SQL. It is a module constant now.
  - **Window start versus end:** the window check read the start column, and reading the end was the same, because the schema sets both or neither. The reader now names its columns.

## 6. Test

- `make check` passes offline with 1416 unit tests, and 1 skipped because the network test only runs in CI. Of these, 36 are new: the E18 counter effects, content sanitizing and `EvidenceDraft`.
- `make test-integration` passes with 272 tests. Of these, 71 are new: 33 for the ledger, 30 for evidence and 8 for the scripted model.
- 16 four-way parallel runs of the integration suite all passed.

**Limits:**
- **The scripted model doesn't publish.** A finished script returns with the attempt still running. Publication is T3.12.
- **A budget denial ends the script quietly.** The fallback report that should follow is T4.8.
- **Evidence is committed per step without a tool call row,** so `tool_calls` quotas aren't exercised yet (T4.3).
